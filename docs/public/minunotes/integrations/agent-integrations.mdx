MinuNotes supports several integration paths for agents and tools. They all use the same scoped permissions model.

## Recommended paths

- **Pi tools** (`minunotes_*`) for coding agents with the local extension installed and loaded.
- **Harness API** for authorized direct HTTPS use when registered tools are unavailable.
- **Hosted MCP** for MCP-native hosted agents and shared runtimes.
- **Local MCP** for desktop clients that spawn local MCP processes.
- **OpenAPI** for actions, REST tool importers, and compatibility with non-MCP platforms.

## Permissions model

Create one API key per agent or project. Keys can use **All non-private folders**, **Project roots**, or **Specific folders**.

Project roots are top-level folders that behave like lightweight workspaces for agents. Folder rules can apply to an exact folder or subtree; the nearest applicable rule wins. With restricted access, a matching rule is required.

Global Read, Create, Edit and Comment capabilities are a maximum ceiling: folder rules can restrict, never expand them. For All access, an unconfigured folder inherits that ceiling. Folder-level “Read-only for agents” normally blocks writes; an applicable exact rule with Specific access is an existing intentional exception, after all other capability and policy checks. Enable folder creation only when explicitly allowed.

Private folders are never accessible to agents or integrations. Private status also applies to child folders.

## Shared collaboration access

Authenticated notes and folders shared with the connection owner are disabled for integrations by default. Choose **No shared content**, select active grants with **Specific**, or explicitly allow **All current and future shared content**.

Effective shared access cannot exceed the human Viewer, Commenter, or Editor role. It also remains bounded by connection capabilities, OAuth scope, private/read-only owner policy, and note API-editability. Downgrades and revocations apply immediately.

Full note reads include privacy-safe role/source context. Discovery stays compact, and direct-note grants intentionally omit folder context. Content created by an Editor's agent in a shared folder belongs to that folder owner and is attributed to the authorizing user. Integrations cannot reshare, administer public links, move shared resources, restore, permanently delete, or generally manage Trash. Edit-capable integrations may move only eligible creator-owned content to the owner’s Trash.

Trashed notes, templates, and folder subtrees are unavailable to integrations. Harness, OpenAPI, hosted MCP, local MCP, OAuth, and API-key clients cannot list Trash, restore, or permanently delete content. Focused destructive operations can move eligible creator-owned notes and folders to the owner’s Trash after explicit approval. Owners perform restore and permanent deletion in the authenticated web interface.

## Properties, templates and discovery

Harness, hosted/stdio MCP and the updated Pi adapter support folder-schema reads and controlled owner mutations, note-property reads/patches, and assigned-template list → preview → reviewed creation. Properties use stable IDs and independent schema/value revisions, not the body hash. Creation uses a reviewed snapshot, complete final tags/values, one request ID and frozen date/time literals; uncertain retries retain that exact payload. No automatic write retries.

Discovery is bounded and cursor-paginated. Continue only when another metadata page is needed, with the same query/filters; never expand every note by default. Direct-note grants have null folder context—do not reconstruct hidden ancestry.

Boards are property-only: owner-selected Select columns and up to 12 stacked values-only Card properties, with no special Type badge or tag-driven placement. Board configuration, personal filtering/sorting, folder duplication, owner template defaults and destructive option deletion remain web-only on these agent surfaces. Non-destructive schema archive, ordinary tags, comments and authorized MCP Trash remain separate.

Installed files do not reload current tools, and source capability does not prove deployed availability. Check the registered inventory; do not switch transports after denial. See [Harness API](/resources/harness-api), [MCP](/resources/mcp) and [Skills](/resources/skills) for workflows and adapter selection.

## Core endpoints

```txt
GET /v1/harness/folders
POST /v1/harness/notes
GET /v1/harness/folders/:folderId/properties
PATCH /v1/harness/folders/:folderId/properties
GET /v1/harness/notes/:noteId/properties
PATCH /v1/harness/notes/:noteId/properties
GET /v1/harness/folders/:folderId/templates
GET /v1/harness/folders/:folderId/templates/:templateId/preview
POST /v1/harness/notes/from-template
POST /v1/harness/notes/:noteId/edit
POST /v1/harness/canvases
POST /v1/harness/canvases/from-syntax
PUT /v1/harness/notes/:noteId/canvas
PUT /v1/harness/notes/:noteId/canvas/from-syntax
POST /v1/harness/notes/:noteId/canvas/nodes/:nodeId/link-note
DELETE /v1/harness/notes/:noteId/canvas/nodes/:nodeId/link
GET /v1/harness/notes/:noteId/outline
GET /v1/harness/notes/:noteId/events
GET /v1/harness/tags
PUT /v1/harness/notes/:noteId/tags
GET /openapi.json
POST /mcp
```

Use `X-API-Key` for direct `/v1/harness/*` API and OpenAPI-authenticated requests. Hosted MCP uses OAuth bearer tokens at `/mcp` (`Authorization: Bearer mnoac_...`). Local stdio MCP uses an owner-managed API key in the local process environment and calls the harness API.

For generated canvases, use the syntax harness endpoints: they auto-detect Mermaid `flowchart`/`graph` headers and otherwise use Minu diagram syntax. Mermaid's supported flowchart subset becomes editable native JSON Canvas, not SVG; imports are limited to 100,000 source characters, 500 native nodes, 1,000 edges, and 16 subgraph levels. Unsupported features return diagnostics. Use Minu syntax for mind maps and raw JSON Canvas for exact import or deterministic replacement. Syntax replacement regenerates the whole canvas and can replace node IDs, positions, links, and metadata; use focused node-link operations for internal note targets.

MCP exposes canvas lifecycle and note-link operations, note outlines and events, and user-facing tag behavior. Broader outgoing-link, backlink, orphan, and graph inspection tools remain deferred until MinuNotes has corresponding product UI semantics.
