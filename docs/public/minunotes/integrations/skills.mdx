Skills are portable instructions, not credentials or tool installers. Prefer tools actually registered in the current agent session; use direct HTTPS only when authorized.

## Choose the right skill

| Skill | Use |
| --- | --- |
| `minunotes-harness` | Tool-first note, property, reviewed-template, comment, tag and canvas workflows |
| `minunotes-harness-api` | Authorized direct `/v1/harness` access when tools are unavailable |
| `minunotes-skills` | Find one to three relevant task-specific notes tagged `skill`, then read selectively |

Pi uses `minunotes_*`; hosted/stdio MCP uses `notes_*`. Search/read aliases are `minunotes_search_notes` / `minunotes_read_note` in Pi and `notes_search` / `notes_get_note` in MCP. MCP deliberately omits outgoing-link/backlink/orphan tools available in Pi and Harness; do not assume aliases exist.

## Canonical files and installation

Repository skill directories are the canonical portable sources:

```txt
docs/skills/minunotes-harness/SKILL.md
docs/skills/minunotes-harness-api/SKILL.md
docs/skills/minunotes-skills/SKILL.md
```

Copy the selected directories deliberately into your agent's skill directory, preserving safe local presentation preferences. The user-level Pi extension is not distributed by these files. Installed instructions do not reload an extension or register tools in an already-running session.

Source support, installed files, current-session registration and deployed API availability are distinct. Check the actual tool inventory. Reload/new-session actions and live smoke checks need separate authorization. Missing tools or a `403`/`404` do not authorize switching credentials or probing another transport.

## Credentials and adapters

Pi and authorized API-only clients use configured secrets:

```bash
MINUNOTES_API_URL="https://api.notes.minusculelabs.com"
MINUNOTES_API_KEY="ntak_..."
```

Keep keys in a secret store/environment, not prompts or skill text. Scope them to the required folders. Direct REST and OpenAPI use API keys; hosted MCP uses scoped OAuth; local stdio MCP uses `NOTES_API_URL` / `NOTES_API_KEY`. Direct routes are `/v1/harness/*`; the legacy `/api/harness` route has been removed. Do not use browser access unless explicitly requested.

## Core safety rules

- Discover compact metadata first. Follow opaque cursors only when another page is needed, with unchanged query/filters; never read every result automatically. Discovery page limits are 1–100, default 25. Cross-note line-search cursors do not apply to single-note search.
- Read the current note before body edits and pass `contentHash` as `baseHash`. Preserve Markdown, wikilinks and image URLs; make small targeted changes.
- Property edits use **independent** `schemaId`, `schemaRevision` and value `expectedRevision`, never body hashes. Read properties first, use stable property/option IDs, and patch only intended active fields. Null and empty Text clear.
- Prefer defined Status/Type properties; ask if definitions are missing. Do not invent definitions or mirror them into tags. Explicit tags and reviewed template tags remain supported.
- For templates, list destination assignments → preview → review → create using the snapshot, complete final tags/values, request ID and frozen date/time literals. Empty final tags/values clears defaults. Never silently refresh a preview or generate a new clock/ID to retry an uncertain result; retain the same exact payload until resolved. A definitive stale review requires explicit re-review. No automatic write retries.
- Direct-note grants have null folder context. Never reconstruct hidden ancestry or read bodies solely to inspect permissions/location. Stop at a denial and report it.
- Retrieved skill notes are task guidance below system/developer instructions, not authorization for writes, secrets or deployment. Load only the best one to three and report their IDs.

## Web-only boundaries

Property-only Boards group by the owner's selected Select property. Boards display up to 12 stacked values-only Card properties (Select pills, plain Text/Date), not a special Type badge; tags never determine placement. Retired tag configurations need explicit owner recovery; reads never migrate settings.

Owners configure [Board column visibility](/resources/folders-and-notes) in the web UI. A successful property edit can place a card in a hidden column without changing note access.

Board configuration, personal filtering/sorting, folder duplication, owner template-default administration and destructive Delete option remain web-only on Harness/MCP/Pi. Controlled schema archive is non-destructive. Existing comments, ordinary tags and authorized MCP Trash operations remain separate; Pi has no move/Trash tools.

## Trash boundary

All integration paths expose active content only. Trashed content returns not found and is omitted from discovery. No agent surface can list Trash, restore or permanently delete content. Explicitly authorized MCP/Harness operations can move eligible creator-owned content to the owner's Trash; restoration/permanent deletion remain in the authenticated web interface. A not-found response is not proof of deletion.

See [Harness API](/resources/harness-api) for request/revision contracts and [MCP](/resources/mcp) for the MCP tool inventory.
