MinuNotes supports both hosted MCP and local stdio MCP.

## Hosted MCP

Use hosted MCP for cloud agents, shared runtimes, and MCP-native integrations that can connect to a remote HTTP endpoint.

```txt
POST /mcp
GET /mcp
DELETE /mcp
```

Hosted MCP uses OAuth bearer authentication:

```http
Authorization: Bearer mnoac_...
```

MinuNotes validates the OAuth token at `/mcp`, then routes tool calls through internal harness operations using the connected app's scoped permissions. Direct `/v1/harness/*` API access remains API-key based; hosted MCP is the OAuth surface.

OAuth-capable hosted clients can discover authorization metadata from the MCP endpoint. MinuNotes advertises protected-resource metadata and Dynamic Client Registration (DCR), so clients such as ChatGPT can register a public OAuth client automatically instead of requiring manual app setup.

## Local MCP

Use local MCP for desktop clients that launch a process, such as local MCP-compatible tools. Local stdio MCP uses an owner-managed API key from the environment and calls the direct harness API.

```sh
export NOTES_API_URL="https://your-minunotes-host"
export NOTES_API_KEY="ntak_..."
notes-mcp
```

The monorepo can export a standalone MCP package artifact for a future `minunotes-mcp` mirror repo or npm package:

```sh
pnpm export:mcp
cd .release/minunotes-mcp
npm pack --dry-run
```

## Available tools

Folders and notes:

- `notes_list_folders`
- `notes_create_folder`
- `notes_trash_folder` (destructive; requires `confirm: true`)
- `notes_search`
- `notes_get_note`
- `notes_create_note`
- `notes_edit_note`
- `notes_trash_note` (destructive; requires `confirm: true`)
- `notes_move_notes`

Structured reads:

- `notes_search_lines`
- `notes_read_lines`
- `notes_search_note_lines`
- `notes_read_outline`
- `notes_read_section`
- `notes_read_events`

Canvases and internal node links:

- `notes_create_canvas`
- `notes_create_canvas_from_syntax` (Minu syntax or auto-detected Mermaid flowchart; optional `format` override)
- `notes_replace_canvas`
- `notes_replace_canvas_from_syntax` (Minu syntax or auto-detected Mermaid flowchart; optional `format` override)
- `notes_set_canvas_node_note_link`
- `notes_remove_canvas_node_note_link`

Tags:

- `notes_list_tags`
- `notes_read_note_tags`
- `notes_replace_note_tags`

Tool discovery is handled by the MCP protocol. Clients call `tools/list`; MinuNotes registers tool names, descriptions, schemas, annotations, and handlers.

## Shared content

Hosted and local MCP can use authenticated collaboration only when the connection owner explicitly enables `specific` selected grants or `all` current and future grants. The default is `none`. Human role, connection capabilities, OAuth scope, owner safety policy, and note API-editability all remain ceilings.

Full note reads return privacy-safe role/source context. Discovery stays compact, and direct-note grants omit folder context. Content created in shared folders belongs to the folder owner and is attributed to the authorizing user. Shared moves, resharing, public-link administration, restore, permanent deletion, and general Trash management remain owner-only. Edit-capable integrations may move only eligible creator-owned content to the owner’s Trash. Revoked or downgraded access fails immediately; clients should report the boundary rather than probe or retry unrelated resources.

For net-new content, resolve the target folder from folder metadata and create directly. Do not read unrelated notes merely to confirm the folder or inspect permissions.

Move operations are all-or-nothing, capped at 100 owned notes, and require edit access to every source folder plus create access to the target folder. Shared notes cannot be moved.

## Canvas JSON versus Minu syntax

Use JSON Canvas for exact imports and replacements where node IDs, positions, external URLs, internal links, and metadata must remain deterministic.

Use Minu diagram syntax for mind maps and Minu-specific layouts:

```txt
diagram "Product plan" {
  layout mindmap
  Product
  Product > Research
  Product > Build
}
```

The syntax tools also auto-detect Mermaid `flowchart`/`graph` input and compile the supported flowchart subset into editable native JSON Canvas (not SVG). It supports the standard directions, basic node shapes, labeled directed/undirected/bidirectional/dotted edges, and nested subgraphs; styling, actions, rich labels, and other diagram types are rejected with diagnostics. Imports are limited to 100,000 source characters, 500 native nodes, 1,000 edges, and 16 subgraph levels. Use `format: "minu"` or `format: "mermaid"` to force a parser. Unsupported Mermaid syntax creates no partial canvas. Syntax is compiled into JSON Canvas; replacing from syntax regenerates the complete document and can replace node IDs, layout, links, and metadata. Use the focused node-link tools after generation when nodes need internal note targets.

Canvas replacement and node-link mutations require a current `baseHash`. Setting a node link creates or changes its internal target; removing it only removes the internal target. Both operations preserve the node’s external `url` and unrelated metadata.

## Current MCP boundary

Hosted and local MCP expose active content only. Trashed notes, templates, and folder subtrees disappear from list, search, read, metadata, and attachment operations. MCP provides explicitly confirmed destructive tools to move eligible creator-owned notes and folders to the owner’s Trash. MCP cannot list Trash, restore, or permanently delete content; those owner-only actions remain in the authenticated MinuNotes web interface.

Tag operations are exposed because tags already have user-facing Note Details behavior. Broader graph tools for outgoing links, backlinks, and orphan discovery remain deferred until their product and UI semantics are established.
