### Approved implementation contract

- `GET /v1/harness/folders/:folderId/notes?limit=25&cursor=...`: compact ordinary-note metadata (Markdown/canvas/mind-map, not templates), SQL title/ID keyset pagination, maximum 100, no content fetch. Opaque cursors bind actor/authorization/folder/query identity. A note-only grant never authorizes folder listing.
- `POST /v1/harness/notes/:noteId/rename`: strict `{ title, expectedTitle }`. `expectedTitle` is the exact original title obtained from current metadata/read; new title is trimmed, nonempty, maximum 1,000 characters. Compare-and-set the title in a transaction, with current read/edit scope and API-editability checks. A body hash alone cannot detect a newer title. This operation never changes content, identity, properties, document type, creation date or location. Reuse native version/event/link-resolution helpers transactionally. Return compact metadata and unchanged contentHash; do not disclose containing-folder context on shared rename responses. No automatic retry; conflicting or uncertain results require review.
- MCP tools: `notes_list_folder_notes`, `notes_rename_note`. Pi: `minunotes_list_folder_notes`, `minunotes_rename_note`. Adapters forward literal IDs/cursors/expectedTitle, validate bounds and never retry mutations or fetch all pages automatically.
